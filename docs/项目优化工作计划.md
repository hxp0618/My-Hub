# My Hub 项目优化工作计划

## 目标

把 My Hub 从功能完整的浏览器工作台，推进到更稳定、可维护、可发布的扩展产品。第一阶段优先处理质量闸门、隐私安全、类型稳定性和基础体验一致性；第二阶段再扩展更有差异化的新功能。

## 第一阶段：工程质量与发布可信度

- 补齐 `typecheck`、`lint`、`test`、`build` 四类本地质量检查，并让它们可以纳入 CI。
- 修复当前 TypeScript 类型断点，重点覆盖全局搜索结果、LLM 消息类型、工具动态导入、React ref、第三方库声明。
- 修复 Vitest 测试环境的 localStorage 问题，稳定属性测试结果。
- 迁移 ESLint 9 flat config，恢复项目文档中要求的 lint 工作流。
- 减少生产日志，避免在后台脚本和 AI 整理流程里输出 URL、通知内容、密钥路径等敏感信息。

## 第二阶段：隐私、安全与权限收敛

- 将导入导出拆成“普通数据”和“敏感数据”两档，默认不导出 LLM Key、Bark Key、通知历史。
- 为敏感配置增加脱敏预览和二次确认。
- 将 `<all_urls>` 内容脚本改为按需注入或最小匹配范围，减少商店审核风险。
- 梳理 `clipboardRead`、`tabs`、`sessions` 等权限的实际使用入口，在设置页补充权限说明。

## 第三阶段：架构拆分

- 拆分 `src/pages/background/index.ts`：书签同步、Bark 定时任务、订阅提醒分别独立模块。
- 拆分 `BookmarkPage.tsx`：页面容器、工具栏、弹窗、拖拽排序、批量操作各自成模块。
- 将 localStorage、IndexedDB、chrome.storage.local 封装为统一 repository，统一迁移、校验和导入导出。
- 把工具箱改为 manifest 注册机制，减少新增工具时需要同时修改 enum、metadata、loader、i18n 的重复工作。

## 第四阶段：UI/UX 与主题一致性

- 清理旧 `.btn-*` 样式，统一到 `nb-*` 组件令牌。
- 将输入框 focus 从蓝色 glow 改为 Neo-Brutalism 硬阴影。
- 将主题元数据、空状态、错误提示全部纳入 i18n。
- 为移动或窄屏增加侧边栏折叠逻辑，避免固定宽度影响可用性。

## 第五阶段：新功能建议

- 命令中心：在统一搜索里支持 `tool:`、`tag:`、`url:`、`action:` 前缀，快速打开工具、搜索标签、执行批量动作。
- 书签健康报告：检测重复、失效、无标签、长期未访问、可归档项目，并给出一键整理建议。
- AI 整理预演：展示 diff、风险提示、置信度、撤销快照，支持只应用选中的整理项。
- 订阅到期日历：按月历/时间轴展示订阅，统计月/年支出，并联动 Bark 与浏览器通知。
- 工具工作流：允许把多个开发者工具串成流水线，例如 URL 解码 -> JSON 格式化 -> Diff。

## 敏感数据导出优化记录

- 设置页数据管理区域新增“包含敏感配置”开关，默认关闭，并用绿色提示说明安全导出行为。
- 用户显式开启完整备份时，界面显示风险提示；点击导出前会弹出二次确认，避免误导出可用密钥。
- 完整备份的二次确认从浏览器原生 `confirm` 迁移到应用内确认弹窗，确保敏感导出风险提示符合 Neo-Brutalism 主题、键盘关闭和中英文 i18n 体验。
- 数据同步底层函数不再直接调用浏览器 `alert` 或强制刷新页面；设置页统一用 Toast 展示导出/导入失败和导入成功，并提供“重新加载页面”操作。
- 为 LLM、Bark、订阅通知配置的脱敏逻辑补充单元测试，覆盖密钥清空、通知渠道禁用和“不修改当前浏览器配置”的回归要求。
- 导入安全导出的备份时，空密钥不会覆盖本机已有 LLM Key、Bark Key 和订阅通知密钥；完整导出中显式包含的密钥仍会按导入文件恢复。
- 无可用设备密钥的 Bark 脱敏条目会在导入时跳过，避免生成选中但不可发送的空 Key。
- 已在真实 Google Chrome 中校验：新设置项、默认安全提示、敏感模式风险提示和二次确认弹窗均可正常显示。
- 复跑 `lint`、`typecheck`、`test`、`build:chrome`，自动化验证均通过；当前测试数为 4 个测试文件、68 个测试。
